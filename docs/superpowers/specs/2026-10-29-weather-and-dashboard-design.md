# 天气助手与管理界面设计

## 目标

为现有 NoneBot 机器人提供和风天气查询和可配置推送，并提供用于查看和管理记忆、群话题的局域网管理界面。

## 天气助手

- 借鉴 AstrBot 天气助手的实时天气、天气预报和主动推送交互，适配现有 NoneBot 和 SnowLuma，不安装 AstrBot。
- 支持城市天气命令和自然语言提问；城市不明确时向用户询问，不凭空猜测。
- 管理员配置推送对象、城市及北京时间，默认没有推送任务；机器人重启后任务仍保留。
- 使用和风天气 API Host 和凭据，由管理员自行配置；采用受支持的接口，展示数据来源，并对请求失败、配额或位置不明确提供明确提示。
- 限制重复请求、设置合理超时；不得将密钥写入日志或聊天。定时推送不默认开启。

## 管理界面

- 单独提供轻量 WebUI，局域网访问，管理员登录后才能访问数据和操作；密码安全存储，敏感接口检查登录、请求来源和跨站请求。
- 展示按用户分组的记忆、候选和开关，支持已有记忆管理能力；展示每个群的话题统计与开关，支持开关和清除。
- 调用现有记忆与群话题模块的管理函数，保留版本控制、向量更新和清除语义，不直接绕过数据一致性处理。
- 天气服务配置和推送任务可以在界面管理；密钥仅用于保存和调用，不向浏览器再次展示原值。
- 不新增数据库服务或额外模型；部署前备份涉及变更的已有文件，验证后重启必要服务。

## 权衡与边界

- 时间推送只发送给管理员指定的私聊或群。无用户设置的地点时请求具体地点。
- 天气结果和会话位置会发送给和风天气；实际计费取决于 API 用量和账号订阅。
- 管理员可查看用户记忆，局域网 HTTP 不提供传输加密，密码和内容仅应在可信网络使用；需要跨不可信网络访问时另行配置 HTTPS 或隧道。
- 保持群话题默认关闭和现有个人记忆的聊天权限规则。
