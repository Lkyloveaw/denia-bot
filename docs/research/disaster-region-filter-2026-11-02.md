# 气象地区过滤误推修复（2026-11-02）

## 线上症状与原因

本地过滤已开启，省份为空，城市设置为“杭州市滨江区、杭州市上城区、杭州市滨江区、杭州市西湖区、杭州市萧山区”。配置最后保存于 2026-11-01 18:32:31 +08:00。

事件库确认 2026-11-02 12:05:57 +08:00 的“海南省发布海上雷雨大风黄色预警信号”状态为 `pushed`，成功投递到两个目标；陕西省级预警也出现相同现象。海南部分县级预警则被正常过滤。

原因是 `disaster_china_logic._region_match()` 在预警地区字段为空时返回 True。省份配置为空不作限制，省级预警的城市字段又为空，因此两道判断都放行。原来的双向字符串包含匹配还会把“杭州市滨江区”匹配为整个杭州，不检查区县。

`.气象预警` 查询原本直接显示全国缓存，未套用地区过滤，属于另一条显示外地预警的路径。历史事件库则按设计保留所有被接收的事件，用于审计。

## 修复行为

- 配置了地区限制但上游缺少对应信息时，不再直接放行。
- 根据上游省、市、区县字段组合完整路径，允许省市区县后缀省略；不再用任意字符串包含关系匹配。
- 配置整个城市时可匹配其所有区县；配置完整区县时只匹配该区县。多地区内部 OR，省份和城市/区县两组限制仍为 AND。
- 上级预警需要行政编码确认其发布层级，且完整地区路径能够确认归属。沿用地图模块已支持的 Jian ID 格式识别编码；不联网查询地理归属。
- `杭州市滨江区` 可匹配编码确认的杭州全市预警；`浙江省杭州市滨江区` 还可匹配浙江省级预警。仅填写杭州区县无法证明其与某个省级预警的关系，因而不放行省级预警。未改动用户现有配置。
- 查询命令实时读取当前配置，先按地区和颜色筛选，再截取请求数量。缓存和历史库仍保存外地事件。
- 城市/区县配置支持多个名称去重，单项最多 40 字、总长最多 600 字。原配置为 34 字，没有被旧限制截断；扩容用于后续完整路径和更多地区。
- 面板同步说明新行为。仅按气象地区筛选时允许不填经纬度；台风、地震的既有距离规则未修改。
